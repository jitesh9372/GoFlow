Problem Statement & Solution
The Challenge
Why Mumbai Transit Needs Intelligence

Mumbai has 21 million daily commuters across trains, metro, and buses — yet no unified platform provides real-time crowd intelligence and multi-modal route planning.

😰 Problem 1 — No Real-Time Crowd Visibility
Commuters have zero visibility into crowd levels at stations before they travel. Rush-hour surprises lead to missed trains, crushed coaches, and wasted time.
🗺️ Problem 2 — Fragmented Multi-Modal Routing
Getting from A to B in Mumbai involves switching between trains, metro, and BEST buses. No single app combines all three with live timing and crowd data.
🚆 Problem 3 — Train Tracking is Opaque
Where is my train right now? Is it late? Which platform? Indian Railways data is scattered and hard to consume. Passengers are left guessing.
📊 Problem 4 — Admins Lack Operational Dashboards
Transit authorities have no consolidated real-time dashboard to monitor crowd levels, passenger reports, and alerts across the entire Mumbai network.

Our Answer
GoFlow — One Platform, All of Mumbai
✅ Solution 1 — Live Crowd Intelligence Map
Interactive Leaflet.js map with real-time crowd indicators at every Mumbai station — colour-coded Low / Moderate / High / Packed — powered by Firestore live data.
✅ Solution 2 — Intelligent Multi-Modal Route Planner
Plan routes across Local Trains, Metro, and BEST Buses in one query. Multiple route options with crowd levels, estimated time, platform info — with save & bookmark.
✅ Solution 3 — Live Rail Radar (RailRadar API)
Real-time GPS telemetry for 70+ Indian Railways trains. Search by train name or number, view live position, next halt, running delay, and full coach composition.
✅ Solution 4 — Admin Operations Command Centre
A full admin portal with real-time crowd monitoring, passenger rush reports review, notifications broadcast, transport management, and analytics dashboards.

Admin Portal
Operations
Admin Command Centre

A full operations portal for transit authorities to monitor, manage, and respond to Mumbai's live transit network in real time.

📊 Admin Dashboard — Real-Time Overview
Central command screen with live KPIs: active stations, crowd alerts, pending passenger reports, Firestore real-time activity feed, network health status, and quick-action buttons for broadcasting alerts.
🚉 Transport Management — Lines & Stations
Full CRUD for Mumbai's transit network: Create/Edit/Delete transit Lines (Western Railway, Central Railway, Metro Line 1, BEST routes). Create/Edit/Delete Stations with geo-coordinates, platform count, and transport mode. Link stations to lines with sequence and timing data.
👁️ Live Crowd Monitoring
Real-time crowd level monitor across all stations. Colour-coded heat view (Low / Moderate / High / Packed). Filter by transport mode. See live readings stream in from sensors and passenger reports. Trigger immediate alerts.
📈 Crowd Analytics Dashboard
Historical analytics with charts: peak hour patterns, busiest stations, congestion trends by day/week, report submission volume. Helps plan service frequency adjustments and resource allocation.
📋 Passenger Rush Reports Review Queue
Review all citizen-submitted crowd reports. Admin can Verify (publish as official data) or Reject (discard incorrect reports). Verified reports feed back into the live crowd map. Filter by: Pending / Verified / Rejected.
🔔 Notifications & Congestion Alerts
Broadcast service alerts with severity: Info Warning Alert. Target by transport mode or specific line. Appear in passenger app's notification banner in real-time via Firestore listeners.
⚙️ Admin Settings
System configuration — manage admin accounts, set role assignments, configure API keys (RailRadar), toggle feature flags.
Role-Based Access Control: Firebase Auth with custom role claims. Passengers access /passenger/* routes. Admins access /admin/* routes. Backend validates JWT token role claims. Firestore Security Rules enforce the same at the database layer — Admins write to all collections; passengers only read public data and write their own reports.

Security
Firestore Security Rules & Firebase Project
🔒 isAuthenticated()
Checks request.auth != null. Required for profile writes and notification creates.
👑 isAdmin()
Checks request.auth.token.role == 'admin' OR admin email claim. Required for write access to lines, stations, transport data.
👤 isOwner(userId)
Checks request.auth.uid == userId. Users can only edit their own profile documents.

⚙️ Deterministic Per-Train Position Algorithm
When live API quota is exceeded (HTTP 429), GoFlow synthesises authentic data:

numHash = sum(charCode × position) for train number
cycle = floor((hour × 60 + minute) / 15)
seed = abs(numHash XOR (cycle × 83))
stopIdx = 1 + (seed % validStops)

Every train number produces a different current station, next halt, running delay (0–34 min), and segment progress (28%–88%) — changing every 15 minutes naturally.

Up/Down Direction Awareness: Even-numbered trains (return journeys, e.g. 12952, 11072) automatically get their route reversed with recalculated kilometre distances — matching actual Indian Railways Up/Down numbering conventions.
